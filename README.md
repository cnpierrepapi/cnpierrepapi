## 🤝 Upstream contributions

### DataHub

One thread, running since July 2026, on how [DataHub](https://github.com/datahub-project/datahub) models incidents. DataHub could raise an incident on a table but not on a column, so the metadata model and the docs disagreed about which entity types were actually supported. I took the column case and the documentation.

- [datahub#19115](https://github.com/datahub-project/datahub/pull/19115) · **merged 20 Aug 2026** · Incident support for `schemaField`, so a data quality problem attaches to the column it belongs to instead of the whole dataset.
- [datahub#19405](https://github.com/datahub-project/datahub/pull/19405) · **merged 24 Aug 2026** · The permission check for a column incident asked whether you could edit the column, and nobody holds permissions on a column. It now asks about the parent dataset, which is where permissions actually live.
- [datahub#18685](https://github.com/datahub-project/datahub/pull/18685) · open · Generates the supported-entity table from the metadata model at build time, rather than asking someone to remember to update a page.
- [datahub#18684](https://github.com/datahub-project/datahub/pull/18684) · open · Two self-hosted MCP troubleshooting entries, both from problems I hit myself.
- [datahub-skills#66](https://github.com/datahub-project/datahub-skills/pull/66) · open · A skill that traces which models and dashboards a dataset change is about to break.

The UI half of the column work is built and tested on my fork. I asked before opening it, and the maintainer said the product side isn't settled yet. Fair enough. It waits.

### Google ADK

Building MIGRAGENT on [Google's Agent Development Kit](https://github.com/google/adk-python) turned up four things worth sending back. One issue is mine and is now a pull request, opened after a maintainer asked for it. The other three are threads somebody else opened where I could add the measurement or the workaround that was missing.

- [adk-python#6880](https://github.com/google/adk-python/issues/6880) · open · A custom model class gets one config object holding 35 fields that belong in three different places in the request, and nothing says which is which. Put the tools in the wrong half and the call still returns 200, so your agent silently has no tools. A maintainer checked the field table against the client library and confirmed it.
- [adk-python#6935](https://github.com/google/adk-python/pull/6935) · open · The fix. Instead of documenting where each field goes, it hands the job to the converter the official client already uses, so there's one copy of the mapping and it moves when the library moves. My own hand-written list had already gone stale by two fields in a day, which was the argument. The maintainer reproduced the test run independently, 49 of 49, and passed it on for the second review.
- [adk-python#2425](https://github.com/google/adk-python/issues/2425) · shipped · A design for cancelling a running agent. Another contributor measured that cancelling leaves a sync tool and an async tool in different shapes. I traced where ADK passes the leftover call on to the model and ran it on Gemini. Cancellation landed on main on 1 Oct, with a fix that closes off exactly those leftover calls, and the maintainer who closed it thanked both of us for the investigation.
- [adk-python#2792](https://github.com/google/adk-python/issues/2792) · fixed · Stopping an agent early printed a stack trace for something you chose to do. I posted the `aclose()` workaround and why it works. It's fixed in 2.12.0. Another contributor checked it on main, then I ran my repro against the release: a plain `break` is clean now, ten runs out of ten. The thread stays open for a separate request about turning tracing off.
- [python-genai#782](https://github.com/googleapis/python-genai/issues/782) · open · Thinking spends two to three thousand tokens before writing a character, so any output limit under about 4k is a zero budget dressed as a generous one.

## 🧭 How I work

- **Build on real data.** Live markets, real documents, production lineage. A demo that only works on fixture data has not been tested.
- **Prove it.** A claim should link to a source or settle on chain. I would rather ship a measured result that is inconvenient than a confident one I cannot support.
- **Build for one user first.** If it is not useful to a single named person, scale will not save it.
- **Test on the deployed thing.** Localhost agrees with you. Production does not.
